# Local launcher build 0.20.0

Android 0.20.0 pairs with the unchanged Windows installer 0.6.2. The signed first-run kit uses the existing local certificates. No vehicle was used.

## App grid and menu

- Open directly to app icons and labels without background cards, a Back button, sidebar or page header. App details remain available by touching and holding an icon. Search and local APK installation are shortcuts in the same grid.
- Distinguish Controls settings from the installed Android settings app. Settings, voice, buttons, displays, vehicle shortcuts and updates remain discoverable from the grid.
- Apply a neutral graphite and blue palette across screens, dialogs and first-run checks, with restrained orange voice accents, unboxed Controls icons and quiet static background lighting.
- Default the reviewed central menu assignment to the Controls app grid. Preserve saved assignments and explicit native overrides. Holding the menu invokes the original action once; failed or unavailable replacement targets keep native fallback.
- Clear transient search state on a fresh menu request while preserving it through recreation within the same entry.

## Navigation and state

- Host all normal Compose routes in MainActivity. Keep former screen component names as compatibility aliases. The foreground voice popup and protected installer handshake retain separate Android boundaries.
- Retain navigation and screen state through recreation. Own settings and voice configuration in ViewModels with immutable StateFlow state; keep dialogs, permission and file-picker handoffs at the UI boundary.
- Stop outgoing route collectors and live preview resources. Separate firmware and cluster maintenance models and keep confirmed transactions independent of navigation. Prevent outgoing settings routes from cancelling newer archive operations.

## Driver memory

Driver 1/2/3 recalls saved driver seat and mirror positions. The [driver-memory guide](../DRIVER_MEMORY.md) now describes that workflow. The separate [account-record recovery appendix](../ACCOUNT_RECOVERY.md) documents its narrower technical scope; it does not describe numbered driver memory as account slots.

## Verification and limits

Android 9 and 11 emulator checks cover aliases, Back, menu entry, recreation, search, settings migration, rollback, archives and update UI. Signed upgrades preserve synthetic settings and the per-installation local-channel key. Rendering checks cover finite transitions, animation scale zero, settled/hidden windows and preview release. See the [validation record](../../dist/VALIDATION_0.20.0.json) for exact counts and artifact hashes.

The firmware and operation approval catalogs remain empty. OEM button delivery, ARM64 injection, physical CAN behavior, microphone routing and sleep/wake still need the intended vehicle. Full overseas account restoration remains unavailable. Earlier root-channel and installer checks remain recorded in [0.19.0](../../dist/VALIDATION_0.19.0.json) and [0.19.1](../../dist/VALIDATION_0.19.1.json); they are not new vehicle qualification.
