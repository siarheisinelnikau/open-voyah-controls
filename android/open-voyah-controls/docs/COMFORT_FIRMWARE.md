# Comfort and vehicle compatibility

**Routines and automation** shows the Android Automotive ignition report where the head unit exposes the standard read-only powertrain property. It checks that the property is readable, global, integer-valued and change-driven. An event timestamp from before the current subscription is labeled as an earlier report. Android grants the read to Controls through `CAR_POWERTRAIN`. Owners of a compatible factory lighting menu can use the existing **Open factory lighting controls** shortcut to select Auto. [Android ignition property](https://developer.android.com/reference/android/car/VehiclePropertyIds#IGNITION_STATE) · [Android ignition values](https://developer.android.com/reference/android/car/VehicleIgnitionState) · [Lighting source coverage](HEADLIGHT_STATUS.md)

| Workflow | Available evidence or route | Evidence required for additional automation |
| --- | --- | --- |
| Driving mode, energy mode and regeneration on ACC | The pinned H97C/Y/X implementation reads the actual driving mode via `DRIVING_MODE_SET_FB`. Existing driving-mode memory can save and manually restore it. Android Automotive can report Off, Accessory and On where supported. | Recorded transitions through ACC and vehicle startup on the intended build, their timing relative to mode reset, manual changes and actual feedback for all three mode families. The Android ignition label alone does not establish an OEM readiness or restore window. |
| Forced EV and Smart Save | The existing native catalog has separate Forced EV, Smart, Save and target-SOC plans. | Exact OEM selection and result for the intended Smart Save behavior, verified target command and genuine controller feedback for each supported setting. |
| Automatic ambient headlights | The factory Auto selector hands light decisions to the vehicle. The existing OVC gear automation and native Low Beam/Auto actions set the same selector. | A dedicated OEM control within Auto, or explicit operator-override feedback. A driver selecting the same Low Beam position that OVC last requested may leave the selector feedback unchanged. An automatic return to Auto could override that driver choice. |
| Brightness by ambient light | The Controls window curve on standard Android uses the device sensor. The existing OEM manual brightness command has a factory thermal check and reads back the brightness setting. | A verified illuminance source for the head unit, OLED/LCD thermal and manual-override behavior, exact dimmer authority and display routing on the intended firmware. |
| Wiper maintenance | The existing manual OEM command uses the Park/zero-speed guard. One catalog branch is a toggle. | A position readback, explicit service position request and the required vehicle/service preconditions for automatic use. |
| Battery warming | An automatic or manual heater write needs a qualified factory interface. | Exact pack-temperature, charge and thermal-protection prerequisites with requested and actual heater state. |
| Suspension service and level | Android Automotive can supply the read-only suspension height card where the vehicle exposes the property. | The advertised service-mode interface, equipment admission, live vehicle constraints and a confirmed safe exit on the intended firmware. |
| Fragrance | Factory equipment can expose original fragrance controls. | Equipment and cartridge availability, bounded intensity and timer control, actual state and shutdown behavior. |
| Turn-signal sound | The selected sound can only be changed via a reviewed compatible OEM path. | Exact factory sound option persistence and audibility, confirmation that normal indicators and hazard sound requirements remain intact. |
| Power Hold and wash | Desktop cards wrap the existing recognized commands. | An exact command review row on the installed head unit. The bundled catalog contains no such rows. |

H97C (`f6802h`), H97Y (`f6805h`) and H97X (`f6811`) are the products identified by the inspected CAN adapter. VOYAH FREE 318 running VOYAH OS 6.1.0 in Guest is a separate installation. The displayed version does not establish its Android build, signer, platform interfaces or eligibility for any new action.
