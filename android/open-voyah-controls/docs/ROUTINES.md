# Routines

In Controls, open **Settings → Routines and automation → Routines**. Add steps in the order they should run. A routine can send Android media controls and wait for fixed intervals. The page, session theme, saved desktop layout, and optional app launch complete the routine after its steps. Pin a routine or add it to Quick Actions for manual access. The existing startup schedule can run a routine when opening Controls with its launcher shortcut.

Use **Cancel** during a pause to stop the remaining steps. Leaving the foreground window also stops them. Android media key dispatch requests playback from the current media target and does not confirm that the player changed state. If Android throws while sending a key, Controls stops that run without sending the key again.

Settings archives from before steps remain readable. When restoring a legacy archive over an existing routine with the same stable ID, Controls preserves steps if the archive omits the field. An explicit empty step list clears it. Archives cannot define a shell command or a vehicle write.

On a supported steering-key route, open the steering settings, choose a short or long press, and select **Run saved routine**. The assignment follows the routine's stable ID when you rename it. If the routine is deleted, replace the assignment in steering settings. The existing CAN edge route still requires both gestures to have launchable assignments before it takes ownership of the key.

Add an optional **Voice phrase** when editing a routine. The phrase stays in the local routine library and settings archive. Say it exactly when Controls is listening. A built-in phrase takes priority if a later catalog or recognition language overlaps it.

The offline assistant can run up to three commands in one listening session. For example, say “pause music then mute then play music” and review each result in the voice popup. The popup omits transcripts if that is your voice preference. App launches and custom routines can run as the final command. Vehicle commands in a sequence are limited to the approved comfort controls in the command catalog, with the same firmware, permissions, and live execution checks as a single command. Other physical commands still use their individual flows. A duplicate command or unrecognized segment is skipped. Cancelling the popup prevents further commands. A partial, timed-out, or unconfirmed vehicle request stops the remaining sequence and is never sent again by that listening session.

Under **If–then rules**, select a routine and one or more conditions. Controls supports gear, doors, Android ambient light, battery charge, outside temperature, actual driving mode, and a local time range. The rule runs on a known transition from outside its conditions to inside all of them. Reopening Controls, reconnecting a source, changing the clock, and receiving the first reading after a gap establish a new baseline. Controls rechecks the same sources during a paused routine.

The rule list identifies selected inputs for which the head unit has no current reading. Battery charge uses the authorized Android Automotive battery energy and current capacity properties. Ambient light requires Android's illuminance sensor. Outside temperature and mode require qualified callbacks in the current vehicle session. The available inputs vary with firmware, hardware and permissions. Time ranges follow the device's local clock and cover midnight when the end is earlier than the start. Background rules depend on the existing Controls accessibility service; a rule skips its action when a source or the foreground lease is lost.
